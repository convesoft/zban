Found by the v0.1.0 review: on a body with an unclosed code fence, `update --handoff` exits 0 but `show` returns `handoff: null`, and a second `--handoff` adds a second section (`DES-HANDOFF`, `REQ-HANDOFF`).

- [x] After building the new body, require that reading the handoff back gives the note just written; otherwise fail with `invalid_handoff` and write nothing
- [x] A `VER-HANDOFF` test through the binary covers the unclosed-fence body

## Summary of Changes

- `handoff::write` (`src/handoff.rs`) now reads the new body back with `Handoff::of` and fails with `invalid_handoff`, writing nothing, unless it gives exactly the note just written (its timestamp and text). The guard only compares the read-back result, so it does not depend on the fence rule in `src/markdown.rs`.
- `DES-HANDOFF` records the new failure, `VER-HANDOFF` names the check, and the `invalid_handoff` row in `docs/cli.mara.md` mentions it.
- Tests: the binary test `a_body_with_an_unclosed_fence_refuses_the_note` in `tests/handoff.rs` (fails before the fix, passes after) and the unit test `rejects_a_note_that_would_not_read_back`.
- Checks run: `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test` (all pass), and `mara schema validate` / `mara project validate` (`valid: true`, evaluation complete).
